### Locked finding — Payload email needs an explicit `serverURL`
The adapter alone is NOT enough. `getRequestOrigin` returns `config.serverURL` when set;
otherwise it trusts the request `Host` **only** if that origin is in the CORS/CSRF
allowlist, and returns `''` when it isn't. We had set neither, so `formatAdminURL`
produced a host-less link. **Any Payload deploy that sends email must set `serverURL`.**
Config now falls back `PAYLOAD_SERVER_URL` → `https://$VERCEL_URL` → `localhost:4400`,
so a missing var degrades to a working deployment-URL link instead of a broken one.

### Env vars (Vercel `asecoroba-cms`)
| Var | Production | Preview |
|---|---|---|
| `RESEND_API_KEY` | set (single entry, shared) | same |
| `EMAIL_DEFAULT_FROM_ADDRESS` | `no-reply@ase-cor-oba.site` | same |
| `EMAIL_DEFAULT_FROM_NAME` | `AseCorOba CMS` | same |
| `PAYLOAD_SERVER_URL` | `https://cms.ase-cor-oba.site` | `https://cms-preview.ase-cor-oba.site` |

⚠️ `PAYLOAD_SERVER_URL` is the only one whose value **differs per scope** — it must be
added twice in Vercel. A wrong value silently sends prod users to preview.

⚠️ `RESEND_API_KEY` is read only at **send** time, so a missing/invalid key never fails
the build. **A green deploy is not evidence email works** — always test a real send.
