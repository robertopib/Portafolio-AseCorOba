## R13b — Twin-equivalence test: prove both emitters agree — 2026-08-07

**Permanent.** Closes R13. Records the finding that retroactively justified the whole item, and
two locked decisions about how fidelity is compared.

### Context

`scripts/fetch-content.mjs` (REST) and `cms/src/scripts/export-content.ts` (Payload Local API)
are hand-maintained line-for-line mirrors, ~1,150 lines each, that must emit **byte-identical**
JSON. R13a made the fidelity gate honest — it compares all 14 files against *committed content*
and fails loudly. But it still never compared the twins **against each other**, which is the
actual contract. That was R13b.

Emitted as prompt 2 of 2 after the conductor split R13.

### Feasibility was measured before scoping, and it held

"Separate transform from fetch" across 2,300 lines reads enormous. It wasn't. Each twin funnels
all data access through **one seam**:
- **REST:** everything through `getJson()` (`fetch-content.mjs:121`) via `getGlobal`/
  `getCollection` — 8 call sites, 1 function.
- **Local API:** 9 `payload.find`/`findGlobal` calls, all on the single `payload` object from
  `getPayload({ config })`.

The real first blocker was smaller still: **neither script was importable** — both auto-ran at
module top level and called `process.exit`.

Putting that measurement in the prompt was load-bearing. Without it the task reads like a
2,300-line restructure and either gets refused or done badly.

reconstruction's import graph entirely — **required**, because the `tests` CI job installs root
dependencies only.

### ⚠️ The finding that justifies the whole of R13

**The hand-mirror had already drifted — inside the very commit that created it.**

R13a's `5830a00` wrote `formatFidelityFailure` twice. The two copies shipped with **different
failure text**:
- `scripts/lib/fidelity.mjs:138` — "the two content emitters and the committed content/*.json no
  longer agree"
- `cms/src/scripts/export-content.ts:128` — "the CMS reconstruction and the committed
  content/*.json no longer agree"

Same commit, same hour, already divergent, and nothing detected it until R13b's mirror test ran
for the first time. Conductor-verified at both paths.

**Hand-mirroring does not drift over months. It drifts immediately.** The two 1,150-line twins
have been maintained by hand for the life of this project; this is direct evidence of what that
costs. Fixed in PR #15.

### Locked decisions produced

1. **Compare serialized BYTES, never parsed objects.** The contract is byte-identical JSON
   *text*. An object diff fails in both directions:
   - It **invents** differences — a key valued `undefined` exists in the in-memory object
     (`Object.keys` includes it, `k in a` is true) but `JSON.stringify` drops it, so `deepDiff`
     reports `extra in reconstructed (recon=undefined)` while the files are identical. This was
     R13a's hand-off trap, and it landed exactly where predicted.
   - It **misses** real ones — a key-order change is invisible to an object diff and is *exactly*
     what a hand-edit to one mirrored emitter produces. Demonstrated with an induced swap in
     `site.json`: 299 vs 299 bytes, parsed objects equal, bytes different.
   `deepDiff` now only *explains* a byte failure by naming the path, with an explicit "objects
   equal, bytes differ" branch. Both behaviours are pinned by tests.
2. **A hand-mirror is not a mirror until something checks it.** The `fidelity.mjs` duplication
   was **deliberately not collapsed**: `cms/` is a separate Vercel root directory, every sharing
   scheme puts a generator in front of `next build`, and a broken CMS deploy is far worse than a
   duplicated 60-line helper. Instead the mirror is **verified** — the CMS copies are exported
   and 25 cases drive both implementations over the same inputs. This is the pattern for any
   future cross-project duplication.
3. **The fixture models the twins' depth asymmetry rather than papering over it.** REST reads
   pages at `depth: 2`, the Local API at `depth: 0`; both survive only because every relationship
   read is `typeof x === 'object' ? x.id : x`. The fixture stores ids and projects per request,
   so a twin that loses one of those guards fails. Verified: REST receives the populated
   Categoría object, the Local twin receives `10`, output identical.

### Coverage — stated, as required

**Proven equivalent: all 14 files.** `home`, `about`, `career`, `ui`, `site`, `pages`,
`categories`, `case-studies`, and all six `sections/*`.

**Not covered, named:**
- **Image download** (REST-only, `~:1059-1116`) — not part of the emitted JSON and the Local twin
  has no equivalent, so there is nothing to compare. Skipped via `images: false`.
- **Payload behaviour the fake reader doesn't model** — it implements `depth` and `sort:'slug'`,
  which is all either twin asks for. Access control, drafts, pagination beyond `limit`, and
  locale fallback are not modelled.
- **Branch coverage is broad but not exhaustive** — it deliberately covers both sides of the
  conditionals most likely to drift (all three `*Visible` states including
  `studioLabelVisible`/`roleLabelVisible`; present/empty-string/missing localized values;
  `placement` home|page|both; all four branding groups; every `CASE_STUDY_BODY_SLICE_KEY` block
  plus an unknown one; an unknown page `blockType`) but does not enumerate every field of every
  global.
