## R21 — Media picker can't select an image (R10 regression) — 2026-08-04

**Permanent.** Two locked findings about Payload's admin table that will bite again, plus
the origin of the R23/R24 content-model work.

### Context

The owner reported that on a Proyecto's **Imagen** field, "elegir existente" opened the
Biblioteca de Imágenes drawer but **no row could be chosen**. The only workaround was
"crear nuevo", which re-uploads a duplicate 11–18 MB original to R2 — so the media library
was effectively write-only: 44 images existed and none could be reused. `main` carried the
same config, so **production was affected**.

Diagnosed by the conductor before writing the task prompt (root cause was handed to the
worker, not left for it to find). It was a regression from **R10**, which had put the custom
`preview` Cell first in `defaultColumns`.

The owner also asked for checkboxes/radios, multi-image selection, and `alt` editing inside
the picker. Triage split that off: the affordance half became this task, the rest **R22** —
and multi-select turned out to have no target in the current schema at all (see below).

### Root cause (verified in `@payloadcms/ui`, v3.86)

1. The **first active column is the row's click target**:
   `isLinkedColumn: enableLinkedCell && colIndex === activeColumnsIndices[0]`
   (`providers/TableColumns/buildColumnState/index.js:141`).
2. In a list **drawer** that cell is the *only* select affordance, and its wiring lives
   **only inside `RenderDefaultCell`** — which calls `useListDrawerContext()` and attaches
   `onClick → onSelect({ collectionSlug, doc, docID })`.
3. `renderCell` resolves a custom Cell via `RenderCustomComponent`, which returns the custom
   component and **never renders the `RenderDefaultCell` fallback** (it falls back only when
   `CustomComponent === undefined`). `cellServerProps.onClick` is always `undefined`, so a
   custom Cell **cannot** receive the select handler.
4. R10's `defaultColumns: ['preview', 'alt', 'updatedAt']` put `MediaThumbnailCell` — a bare
   `<img>` with no `onClick` — in that slot. Net effect: **no selectable cell in any row.**
5. **No checkbox fallback exists for this field:** `enableRowSelections: hasMany`
   (`fields/Upload/Input.js:587`), with Payload's own comment at `:301` — *"only hasMany can
   bulk select."* `Projects.image` is single-valued, so row checkboxes are deliberately off.

### What shipped

`defaultColumns: ['filename', 'alt', 'updatedAt']` — option (a) from the prompt, but with
`filename` instead of the suggested `alt`, **which beat the tradeoff the prompt predicted**:

- `cellComponents` has **no `text` key**, so for `filename` `DefaultCellComponent` is falsy
  and `DefaultCell` falls through to its `FileCell` branch
  (`elements/Table/DefaultCell/index.js:115-123`).
- `FileCell` renders a `Thumbnail` **plus** the filename.
- That `CellComponent` is wrapped in `WrapElement`, which becomes a
  `<button type="button">` whenever `onClick` is present (`:73-82`).
- **So the thumbnail itself is the click target.** R10's thumbnail-first list was preserved
  rather than walked back — option (a)'s only stated cost disappeared.

Conductor re-verified this whole chain in source at ingest. `alt` was equally viable
(measured 44/44 populated in both `es` and `en`, so the empty-placeholder risk the prompt
flagged did not exist) but would have demoted the thumbnail. Option (b) — the client wrapper
around `useListDrawerContext` — was rejected: a deep `dist/` import's upgrade risk isn't
worth an outcome (a) already achieves.

The `preview` UI field stays **defined but out of the default layout**: still offered by the
column selector, and keeping it registered left `importMap.js` byte-identical.

**Files:** `cms/src/collections/Media.ts` (defaultColumns + a comment recording the rule at
the config itself), `cms/src/scripts/reset-media-list-prefs.ts` (docstring only).

### Locked findings

1. **Never put a custom Cell in column 0** of any collection reachable from a picker drawer.
   The drawer's only select affordance is the first column, and its wiring is skipped for
   custom Cells. R10 shipped this; R21 fixed it. Now a comment in `Media.ts` so the next
   editor of that config sees it.
2. **Saved column preferences override `defaultColumns`, and the picker drawer shares the
   `collection-media` preference key with the main list.** A stale preference row silently
   defeats any `defaultColumns` change. Not hit here (verified `upsertPreferences` strips
   undefined, and the client persists columns only on explicit user action) — but it is a
   live trap for future column work, and the reason `reset-media-list-prefs.ts` exists.
3. `CLAUDE.md`'s deployment section is factually wrong (cites a nonexistent
   `.github/workflows/deploy.yml` + rsync to SiteGround). Reported as new; **it is R6.** No
   duplicate item created — but two workers have now tripped over it, so it costs more than
   its Low rating suggests.

### Regression-test exemption (deliberate)

`docs/testing-standards.md` requires a bug fix to ship a test that fails without the fix.
Exempted here: no runner exists until **R12**, admin UI is never pixel-tested, and a live
production content blocker must not wait on tooling. **R12 carries the invariant** — assert
`Media.admin.defaultColumns[0]` names a field with no custom `Cell`. Debt recorded, not
skipped. This was the first exercise of the R11 standard's non-negotiable rule, and it
needed an exemption immediately — worth remembering when judging that rule's cost.

### Discovered → R23 / R24

While verifying the fix the owner raised the deeper problem: **a `Projects` row conflates
three concerns** — which asset, which project, and where it appears. Live evidence: 18
records for 12 images in one category; a 7-view shoot held together only by a typed
`internalTitle` prefix; every dual-placement photo stored twice. Full analysis with two
costed options: **`docs/delivery/analysis-projects-vs-photos.md`** (committed here — it was
left untracked by the worker and would have been lost).

Split into **R23** (Option A — CMS-only regroup, exporter flattens to byte-identical JSON,
pixel gate stays 0.000%) and **R24** (Option B — project detail pages, a deliberate public
redesign that breaks the pixel gate by intent and needs a design brief first). R23 depends
on R12 + R13 because it rewrites the exporter R13 owns.

**Also noted there:** this is *why R21 hurt so much* — with 57 image-cards each needing its
own media pick, a broken picker blocks nearly all content work.
