### RELEASE.md step 3 was redesigned, not just corrected

The right call. Schema application is no longer an operator step — it is `payload migrate` inside
the deploy's `ci:build` (`cms/package.json:19`). So:
- **Step 3** is now read-only pre-deploy verification with **no authorization phrase**: confirm the
  migration is committed and wired, then `migrate:status:prod` shows the new one `Ran: No`. Stop if
  it already says `Ran: Yes`. The `export-content.ts` run survives as an optional
  `FIDELITY_GATE=0` content diff.
- **`authorize db migration on production` moved to step 4**, which now takes both phrases.
- **The downtime window moved with it** — no longer "admin 500s from step 3 until step 4" but "old
  CMS code serves against the new schema for the length of `next build`". Shorter, and elsewhere.
- **The R8 failure shape is now documented there**: a failed migration means `next build` never
  runs and Vercel keeps the last good deployment, so **prod looks healthy while serving old code**.

The 2026-07-30 Context block was marked **superseded** rather than deleted — its premise ("dev uses
Payload `push`, prod has no migration files") is *why* the manual runbook exists, and it was the
sentence making the whole file read as current. Deleting it would have destroyed the explanation;
leaving it unmarked was the bug.

### Generalisable finding: state the rule about the import graph, not the path

The standard's old rule *"do not import CMS source from a root test"* was **reworded, not
deleted** — as written it now contradicts the alias pattern used twice (R13b, R29). The real
constraint was never the directory: it is the **transitive import graph reaching
`payload`/`sharp`/`@aws-sdk/*`**, which the `tests` job cannot resolve because it installs root
dependencies only (`ci.yml:265-266`). A rule phrased as a path ban forbids something safe and
permits something broken.

### ⚠️ One proposed backlog item DECLINED — already a settled decision

The outcome proposed filing *"`check-migrations.mjs` check 6 is a WARN, not a gate"* for a
conscious decision. **That decision was already made deliberately in R2**, and is recorded twice:
- `docs/delivery/roadmap.md`, R2 detail — *"'schema change without a migration' is a **warning**,
  not a blocker, because schema-bearing files also carry admin-only changes… a hard version needs
  a real schema diff, which needs a live DB."*
- `scripts/ci/check-migrations.mjs:112-115` — *"Deliberately a warning, not a gate… Promoting this
  to a hard gate needs a real schema diff, which needs a live DB — see the R2 outcome note."*

Filing it would have invited a future worker to re-litigate a Locked decision — the exact failure
this project's Locked-decisions section exists to prevent. **The observation itself was good**:
noticing the gap between "assumed enforced" and "actually advisory" is right, and the answer is
that the gap is known and priced. No item created.

**Conductor rule this reinforces: before filing a discovered item, grep the roadmap and the code
for an existing decision.** A backlog entry that re-opens settled work is worse than no entry.
