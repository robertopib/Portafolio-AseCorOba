## R11 — Project-calibrated testing standards — 2026-08-03

### Context
The repo had **zero tests and zero test tooling** — no runner, no `test` script in either
`package.json`, no test files in either project. The only rule document was
`governance/docs/rules/testing-standards.md`, generic boilerplate in a **submodule shared
with other projects** mandating 80% line coverage, a full unit/integration/E2E matrix, and
a snapshot per presentational component. Applied literally to ~83 mostly-presentational
files with vendored shadcn, that is hundreds of worthless tests.

This task authored the project-local companion standard. **Rules only** — no tooling
installed, no dependency or lockfile change, no CI change, no tests written, submodule
untouched. It unblocks R12 (content resilience) and R13 (fidelity twin).

Executed by the project-local `qa` agent (`.claude/agents/qa.md`), not the generic
governance `testing-qa`.

### Conductor decisions taken while ingesting

- **Finding 1 folded into R13 rather than given its own ID.** They are inseparable in
  practice: you cannot write a meaningful twin-equivalence test on top of a gate that
  hardcodes `match: true` and exits 0. R13's context, acceptance criteria and risk were
  rewritten accordingly (Medium→**High**) — it is now explicitly a repair-then-test task,
  not "add drift detection to a working gate."
- **R16 flagged to fold into R13** as well: same file, same reader, and R13 already
  rewrites that logic.
- **R17 sequenced before or with R12.** R12 must add a tsconfig for the test runner
  regardless, so leaving R17 for later means R12 inherits a surprise pile of pre-existing
  type errors mid-task.
- **R20 is the only backlog item permitted to edit the `governance/` submodule** (same
  caveat as R7 — shared with other projects). Recorded so no future task edits it
  opportunistically.
- **R19's status code is left as an open decision, not a prescribed fix.** The existing
  comment argues 200 is a valid editor-facing state rather than a server error; that is
  defensible. The gap is the *UI* surfacing of `reason`, which the acceptance criteria now
  name.
- **The testing rules were promoted into Locked decisions** rather than left only in
  `docs/testing-standards.md`, because they bind every future task's Definition of Done —
  most importantly "no coverage-percentage target, ever" and "adopting Playwright does not
  reopen visual regression."
