## R12 — Content-resilience tests: the gap CI structurally cannot see — 2026-08-04

### Context

Records the R12 worker outcome. R12 is the task that gave this repo its **first test runner
and first test suite** — until it merged there were zero tests and zero test tooling in
either project. That makes this note unusually load-bearing: the runner shape R12 chose is
what R13 and every later task inherits, and several of its findings are now Locked
decisions rather than task detail.

R12 closed risk 1 in `docs/testing-standards.md` — the structural gap where **CI builds
against committed `content/*.json` fixtures while production rebuilds against the live CMS
via a publish hook that never touches GitHub Actions**, so the deployed site is never the
artifact CI validated.

Merged to `preview` as PR #9 (`4ceeaf0`). Not promoted to `main` — no user-facing change,
and no authorization was requested or needed.

#### Decisions worth keeping

**How unknown `blockType` became loud without changing rendered output.** Unconditional
`console.error` naming the block, the page and the registry; `return null` unchanged. Not a
throw — that unmounts the tree and blanks the page, trading one lost section for the whole
document, which is R18's work. Not dev-only — the failure happens on the production rebuild
against the live CMS, the one environment a dev-only warning cannot reach.

**The same seam exists one layer down, and R12 closed it too.** `CategoryGallery` returned
`null` for an unknown `layoutVariant`. The `blockType` resolves fine, so `PageRenderer` is
satisfied and reports nothing — and the gallery still vanishes. Same treatment, plus a
matching invariant (used ⊆ dispatched).

**Pin the invariant, never the census.** Measured ~3,045 localized pairs against R11's
2,709 — a 12% move in one day of ordinary editing. Asserting a count would redden on the
next legitimate `fetch-content` commit while catching nothing. Counts survive only as
labelled vacuity floors.

**R21's invariant reads source text, not an import.** `Media.ts` reaches `sharp` and
`@aws-sdk/client-s3` through its afterChange hook — CMS deps that neither resolve nor
typecheck from the root project. Read via `?raw`, with assertions that the parse itself
succeeded so a reformat fails loudly instead of passing vacuously.

#### Two findings that changed more than this task

**1. A co-located test file is a Tailwind source file.** `@source` scans `src/**` as *text*,
so class names in an assertion become real CSS rules. Measured: one probe test naming
`line-clamp-2 truncate static` added `.static`, `.line-clamp-2` and `.truncate` to `dist`
and moved the bundle — it would have reddened `pixel-parity` for a change touching no
markup. This is **R17's gotcha arriving at exactly the file layout the standard mandates**.
Fixed with `@source not '../**/*.test.{ts,tsx}'`; CSS verified byte-identical against a
clean `origin/preview` build. **Now Locked.**

**2. Two mutations found real gaps in the worker's own first draft** — the strongest
available argument for the break-the-code rule:
- removing `object-cover` from **one** gallery variant passed against a single-variant test.
  The suite now sweeps all 11 variants from the exported dispatcher, so a variant added
  later is covered automatically.
- breaking the content glob, or the `{es,en}` walker, turned the whole invariant file green.
  Hence the labelled vacuity floors in every suite.

#### Delivery-state defect found and fixed during this ingest

Three earlier conductor commits — `684470e` (R21 ingest), `08ad2aa` (R17 ingest), `17be100`
(R12 prep) — were committed to `fix/r21-media-picker-select` **after** PR #6 had already
merged that branch at `c60b83f`, so they never reached `preview`. The roadmap on `preview`
was 369 lines and three ingests stale: it still showed R12 as `todo`, had no R25/R26 rows,
and carried no R12 item detail. The code those commits describe was merged normally via
PR #6 and PR #8 — **only the bookkeeping was stranded.**

Recovered by cherry-picking all three onto `docs/recover-delivery-log` off current
`preview`, cleanly and with no conflicts (nothing in `4ceeaf0` touched those files), with
the R12 ingest applied on top in the same PR.

**Process lesson worth not relearning:** a conductor ingest committed onto a *task* branch
is lost the moment that branch's PR merges. Ingests must go on their own branch off current
`preview` — which is what `docs/log-r11-outcome` did correctly, and what this note's own
branch does.
