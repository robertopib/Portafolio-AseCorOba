## R13a — Repair the local fidelity gate (+ R16) — 2026-08-06

**Permanent.** Records a conductor error that would have broken production, the asymmetric-gate
decision that must not be "tidied up", and R13b's hand-off.

### Context

`scripts/fetch-content.mjs` (REST) and `cms/src/scripts/export-content.ts` (Payload Local API)
are hand-maintained line-for-line mirrors, ~1,050 lines each, that must emit **byte-identical**
JSON. Both carried a "fidelity gate" meant to catch divergence. It was ~90% decorative.

Emitted as **prompt 1 of 2** after the conductor split R13: (a)+(b) were a surgical same-file
repair; (c) — proving the emitters agree — needs fixture capture and a transform/fetch
separation, and is meaningless against a gate that hardcodes `match: true`. The order was forced.

### What was broken (all re-verified in source before the split)

- Four files bypassed `emit()` and were written straight into `CONTENT_DIR`: `pages.json`
  (`:653`), `categories.json` (`:690`), `case-studies.json` (`:1012`) — each with a hardcoded
  `report[…] = { match: true, diffs: [] }` — and **`site.json` (`:259`), which was absent from
  `report` entirely.** R11's audit listed three; there were four. Absence read as "nothing to
  check", which is why `site.json` stayed invisible.
- **598,916 / 664,086 committed content bytes = 90.2%** reported as matching without ever being
  compared. `pages.json` alone is 537,374 bytes (80.9%).
- **`allMatch` was computed and discarded** — `:1019` computed it, `:1021` wrote it to a temp
  file, nothing read it. `process.exit(0)` at `:1031` sat *outside* the `try/catch`, so a thrown
  exception also exited 0.
- The REST twin's `exit(1)` at `:1092` was a decoy: it fires only from `main().catch(...)`. The
  fidelity path set `allMatch=false`, logged one line, and returned normally → exit 0.

### ⚠️ Conductor error: "both gates exit non-zero" would have broken production

The prompt required *"a mismatch makes **both** twins exit non-zero."* I carried that forward
from R11's original R13 stub **without checking what invokes the scripts.**

`vercel.json`'s `buildCommand` is **`node scripts/fetch-content.mjs && pnpm build`**. That
script is the build's content **producer**, and with `&&` a non-zero exit **aborts the deploy**.
A diff from `git HEAD` is the *normal, correct* outcome of every editor publish — so a
default-on gate there would red every production deploy the moment a word changed. It would
have failed on day one regardless, because `content/pages.json` is already stale w.r.t. both
emitters (R17).

The worker caught it, implemented the correct behaviour, and flagged the deviation explicitly
rather than silently complying. **Generalisable lesson: before requiring a script to exit
non-zero, check what invokes it.** Same shape as the `studioLabel` error in R17 — a claim
inherited and re-asserted without verifying its consequence.

### The asymmetric gate — deliberate, now a Locked decision

Keyed to what depends on each script's exit code:

| Script | Role | Gate |
|---|---|---|
| `export-content.ts` | verification tool, nothing depends on it | **ON by default**; `FIDELITY_GATE=0` opts out |
| `fetch-content.mjs` | the build's content producer | detects + reports **identically**, exits non-zero only under `--gate` / `FIDELITY_GATE=1` |

**Only the exit code differs between modes** — the full report (file, JSON path, expected vs
actual) prints either way. **Do not "fix" this asymmetry into symmetry.**

### Hand-off to R13b

1. **`deepDiff` compares the in-memory object, not the serialized bytes.** A key valued
   `undefined` exists in the recon object but is dropped by `JSON.stringify`, so the file lacks
   it while `deepDiff` reports `extra in reconstructed (recon=undefined)`. Latent today; **R13b
   compares emitter outputs directly, which is exactly where it bites.** The twins' contract is
   *byte*-identical JSON, which argues for comparing bytes.
2. `scripts/lib/fidelity.mjs` is the natural home for shared comparison code, and
   `tests/fidelity/` already exists inside `vitest.config.ts`'s `include`.
3. **The duplication is the root cause R13b was scoped around.** `export-content.ts` mirrors
   that module **by hand**, because `cms/` is a separate pnpm project with its own Vercel root
   directory — `../../../scripts/…` would not resolve in the CMS deployment. Collapsing it, or
   separating each twin's transform from its fetch so both can be driven over one fixture, is
   the real deliverable.
4. `content/pages.json` remains stale w.r.t. both emitters (R17) — the equivalence test must not
   read that as induced divergence.
