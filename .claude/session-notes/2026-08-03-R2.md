### Context
`.github/workflows/` was empty, so every regression was caught in production or by
luck: a committed `migrations/index.ts` importing a deleted migration broke the CMS
build and Vercel silently served a stale deploy for days (R8); a root `pnpm add`
updated the wrong lockfile; `payload-types.ts` can drift; the 0.000% pixel gate was
only ever run by hand.

### Content
**Status: done (preview).** Preview-only, no authorization phrase needed. No app,
schema, migration, or public-render change — the diff is 4 files:
`.github/workflows/ci.yml`, `scripts/ci/check-migrations.mjs`,
`scripts/ci/check-lockfiles.mjs`, and a 6-line `CHROME_PATH` override in
`scripts/shoot.mjs` (unset = unchanged macOS behaviour).

Four jobs, on PRs **and** pushes to `preview`/`main`, `concurrency` cancels stale runs:

| Job | Time | Checks |
|---|---|---|
| `repo-integrity` | ~15s | migrations `index.ts`↔disk (both directions), `push: false`, two-lockfile invariants. No install, so it fails fast. |
| `cms` | ~1m | `pnpm install --frozen-lockfile --ignore-workspace` (mirrors `cms/vercel.json`), `payload-types.ts` drift, admin `importMap.js` drift, `next build` |
| `site` | ~30s | `pnpm install --frozen-lockfile`, `vite build`, output assertion |
| `pixel-parity` | ~3m | PRs only: shoot merge base + head on one runner, 0.000% required, diff PNGs uploaded on failure |

`next build` *is* the typecheck — no `ignoreBuildErrors` — so no separate `tsc` step.
The site has no TypeScript dependency at all; `vite build` is the whole gate there.

### Locked finding — the pixel gate cannot use `screenshots/baseline` in CI
Two independent blockers: `screenshots` is **git-ignored** (46 MB, not on the runner),
and the baseline is **macOS-Chrome-rendered**. Measured Linux Chrome vs the committed
baseline: **all 24 shots differ, 0.084%–1.449%, with byte-identical page dimensions.**
So layout is fully portable and only text rasterization differs — but against a
0.000% gate that fails every PR regardless of the change.

Repeat runs on one platform measured **0.000% across all 24**. Hence the design:
**shoot merge base and head on the same runner and diff those.** Rasterization
cancels out, nothing needs committing, and it answers the question a PR actually
asks — "does this change alter a rendered pixel?" — rather than "does this runner
render like the owner's Mac?" The local `shoot.mjs` + `screenshots/baseline` workflow
is unchanged and still the owner's tool.

Alternative, if a committed baseline is ever wanted: generate it inside a pinned
container and run the gate in that same container. Rejected here — it puts ~46 MB of
PNGs in git, grows on every legitimate design change, and creates two baselines
(macOS local + Linux CI) that must be regenerated in lockstep.

### Trap — `src/styles/globals.css` is dead code
The first regression probe edited `globals.css` and CI **correctly** stayed green:
nothing imports it. `src/main.tsx` imports only `src/styles/index.css`, which pulls
in `fonts.css`, `tailwind.css`, `theme.css` and the slick CSS. `globals.css` is
unreferenced. Edit `theme.css` for real global style changes; don't trust a green
pixel gate on a `globals.css` edit as evidence the gate is broken.

### What CI deliberately does NOT do
- **`pnpm lint`** — ESLint v9 needs a flat config this repo lacks (R9); it would fail
  every PR for a pre-existing reason.
- **Block on "schema change without a migration"** — warning only. Schema-bearing
  files also carry admin-only changes (labels, custom `Cell`s, hooks) that need no
  migration, so blocking would reject valid PRs. A hard gate needs a real schema
  diff, which needs a live DB.
- **Touch any database.** `DATABASE_URI` is an unreachable placeholder; verified that
  Payload never connects during `next build` or `generate:types`. `payload migrate`
  runs only in Vercel's `ci:build`, never in CI. No secrets are committed or needed.
- **Run `fetch-content.mjs`** — it needs the live CMS. Committed content keeps CI
  offline and deterministic; a CMS outage cannot redden a PR.

### Human follow-up (required for the gate to actually block)
GitHub does not infer required checks from a workflow. Settings → Branches → add
rules for **`main`** and **`preview`** requiring: `Repo integrity (migrations,
lockfiles)`, `CMS (frozen install, type drift, build)`, `Site (frozen install,
build)`, `Pixel parity (head vs merge base, 0.000%)`. Note `pixel-parity` only runs
on `pull_request`, so merges must go through a PR for it to gate — which also means
the current practice of pushing straight to `preview` skips it.
