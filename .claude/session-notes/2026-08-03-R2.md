### Content

`scripts/ci/check-lockfiles.mjs`, and a 6-line `CHROME_PATH` override in

Four jobs, on PRs **and** pushes to `preview`/`main`, `concurrency` cancels stale runs:

| Job | Time | Checks |
|---|---|---|
| `repo-integrity` | ~15s | migrations `index.ts`↔disk (both directions), `push: false`, two-lockfile invariants. No install, so it fails fast. |
| `cms` | ~1m | `pnpm install --frozen-lockfile --ignore-workspace` (mirrors `cms/vercel.json`), `payload-types.ts` drift, admin `importMap.js` drift, `next build` |

`next build` *is* the typecheck — no `ignoreBuildErrors` — so no separate `tsc` step.

### Locked finding — the pixel gate cannot use `screenshots/baseline` in CI
Two independent blockers: `screenshots` is **git-ignored** (46 MB, not on the runner),
and the baseline is **macOS-Chrome-rendered**. Measured Linux Chrome vs the committed
baseline: **all 24 shots differ, 0.084%–1.449%, with byte-identical page dimensions.**
So layout is fully portable and only text rasterization differs — but against a
0.000% gate that fails every PR regardless of the change.

Repeat runs on one platform measured **0.000% across all 24**. Hence the design:
**shoot merge base and head on the same runner and diff those.** Rasterization
cancels out, nothing needs committing, and it answers the question a PR actually
asks — "does this change alter a rendered pixel?" — rather than "does this runner
render like the owner's Mac?" The local `shoot.mjs` + `screenshots/baseline` workflow
is unchanged and still the owner's tool.

Alternative, if a committed baseline is ever wanted: generate it inside a pinned
container and run the gate in that same container. Rejected here — it puts ~46 MB of
PNGs in git, grows on every legitimate design change, and creates two baselines
(macOS local + Linux CI) that must be regenerated in lockstep.

### Trap — `src/styles/globals.css` is dead code
The first regression probe edited `globals.css` and CI **correctly** stayed green:
nothing imports it. `src/main.tsx` imports only `src/styles/index.css`, which pulls
in `fonts.css`, `tailwind.css`, `theme.css` and the slick CSS. `globals.css` is
unreferenced. Edit `theme.css` for real global style changes; don't trust a green
pixel gate on a `globals.css` edit as evidence the gate is broken.

### What CI deliberately does NOT do
- **`pnpm lint`** — ESLint v9 needs a flat config this repo lacks (R9); it would fail
  every PR for a pre-existing reason.
- **Block on "schema change without a migration"** — warning only. Schema-bearing
  files also carry admin-only changes (labels, custom `Cell`s, hooks) that need no
  migration, so blocking would reject valid PRs. A hard gate needs a real schema
  diff, which needs a live DB.
- **Touch any database.** `DATABASE_URI` is an unreachable placeholder; verified that
  Payload never connects during `next build` or `generate:types`. `payload migrate`
  runs only in Vercel's `ci:build`, never in CI. No secrets are committed or needed.
- **Run `fetch-content.mjs`** — it needs the live CMS. Committed content keeps CI
  offline and deterministic; a CMS outage cannot redden a PR.

### Branch protection — APPLIED and verified (same session, 2026-08-03)
GitHub does not infer required checks from a workflow, so this was the step that made
R2 real. Applied via `gh api` to **both** `main` and `preview`:

| Setting | Value |
|---|---|
| PR required | yes, **0 approvals** (solo repo — the owner can merge their own PR) |
| Required checks | all 4, incl. `Pixel parity (head vs merge base, 0.000%)` |
| `enforce_admins` | **true** — no bypass, including the owner |
| `strict` | true (branch must be up to date before merge) |
| force-push / deletion | disabled |

**Trap — a "successful" protection apply that protected nothing.** The first apply
set `enforce_admins: false` (intended as a lockout escape hatch). A probe push to
`preview` printed every protection warning — *"Changes must be made through a pull
request"*, *"4 of 4 required status checks are expected"* — **and then succeeded
anyway** (`88e20e4..0d815df`), because admins bypass all of it. The warnings look
identical to a rejection. Enforcement had to be enabled explicitly
(`POST …/protection/enforce_admins`), after which the same probe gave the real
result: `! [remote rejected] preview -> preview (protected branch hook declined)`.
**Always verify protection with an actual push, not the API response.**

**Consequences, now binding (also in roadmap Locked decisions):**
- **Direct pushes to `preview` are rejected.** Every task from here works on a
  feature branch and opens a PR. This is what makes `pixel-parity` — a
  `pull_request`-only job — gate preview work at all.
- **No bypass if CI itself breaks.** A GitHub Actions outage or a workflow bug blocks
  all merges. Escape hatch:
  `gh api -X DELETE repos/robertopib/Portafolio-AseCorOba/branches/<branch>/protection/enforce_admins`.
- Residue: two empty commits on `preview` (`0d815df`, `git diff 88e20e4..HEAD --stat`
  empty) from the probes. Removing them needs a force-push, which protection now
  forbids; not worth relaxing the rules for.

### Follow-on decisions taken in the same session (QA direction)
The founder challenged whether visual regression is needed at all, on the grounds
that the front page changes constantly via the CMS and CMS-side changes aren't
publicly visible. **Half right, and the answer is now a locked decision.**
- Correct: the admin UI should never be pixel-tested (behind login; Payload owns it).
- Doesn't apply to CI: `pixel-parity` stores **no baseline**, diffs merge-base vs head
  against the *same* committed `content/*.json`, and **editor publishes never trigger
  CI** (`triggerDeploy.ts` has no GitHub reference — publish goes straight to the
  Vercel deploy hook). Content churn produces zero pixel noise. The staleness worry
  applies to the *local* 46 MB macOS baseline, not to CI.
- The real gap the challenge exposed: **CI validates code against a content fixture
  while production renders against the live CMS, so the deployed site is never the
  artifact CI validated.** Content-shaped breakage (a 400-char heading, a portrait
  image where the layout assumes landscape, an empty field a renderer assumes is
  populated) ships unseen. That became **R12**, ranked above any further pixel work.

Also created: `.claude/agents/qa.md`, a **project-local** QA agent, rules-authoring
only. The governance submodule already ships `testing-qa.agent.md`, but it assumes an
existing suite, test utilities and coverage thresholds this repo lacks (**zero tests,
zero tooling, both projects**); its 80%-coverage + snapshot-every-component rules
applied to ~83 mostly-presentational files with vendored shadcn would be pure
busywork. The local agent is told the upstream baseline is not binding, must justify
each departure in a deltas table, and must **never edit the submodule** (shared with
other projects). Its risk ranking: content-shaped breakage (R12) → the fidelity twin
(R13: `fetch-content.mjs` is a hand-maintained line-for-line mirror of
`export-content.ts`, both must emit byte-identical JSON) → publish plumbing →
bilingual `{es,en}` fallback (fails *silently* to Spanish) → migrations (already
gated; cite, don't rebuild). Queued as **R11** (standards) → R12 → R13.
